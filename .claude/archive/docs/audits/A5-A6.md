# Audit A5+A6 — permissions end to end, production readiness and RLS (D-170)

Audit run: 2026-11-12, on `main` at `40b3235` (after 8.4), in a fresh session with a clean verifier subagent for each
finding (D-051). The live production was read only: Supabase project `etmyjbhkqoufoqsjbhev` (the `commands` function)
and Vercel (`sagol.vercel.app`). Nothing in it was written, reset or deleted.
Recorded: 2026-11-12, in the same session under D-170: every finding was accepted, and each question was decided by the
audit (D-186 to D-188). `src/` is unchanged.

## Result

No blocker. On the live database no client reaches a table: RLS is on for 29 of 29 tables with no policy, the API roles
(`anon`, `authenticated`, `PUBLIC`) hold no table, sequence or app-function grant, and `postgres`'s default privileges
keep it that way (D-203). The gateway takes identity from the token only (Google, `email_verified`), admits only
allowlisted methods (`Object.hasOwn`, at most 4 arguments), limits CORS to `APP_ORIGINS`, and answers 401, 413 and 503
before any command runs. Every adapter group scopes to the actor's organization, sets server-owned fields itself and
runs parameterized SQL. The policy matrix passes against the database. Three app-side gaps remain: required properties
for actors who cannot read them, a preference save that fails silently, and a link review that answers a unique before
visibility. Two backend ones: `btree_gist` in `public`, and a live migration history that does not match the repository.

## Questions and answers

Decided by the audit under D-170; the owner was not asked.

1. **Required properties for who cannot read them (OI-113).** The readers widen, the check stays: whoever creates or
   changes an entity reads that entity type's definitions (D-186).
2. **A failed preference save (OI-115).** It says so and shows the stored row; no silent retry (D-187).
3. **Extensions.** In the `extensions` schema, now and for every later one (D-188).
