## What was checked and found in order

- **Server-authoritative behavior:** the actor comes from the session, inputs are strict, every command runs in one
  transaction and a refusal undoes it (D-008, D-045, D-090).
- **Permissions:** reads and commands go through `can()`, invisible rows answer `not_found`, and the tables of D-089
  and D-096 are implemented as written. Creating a soldier is not a second way to place one or to write private
  fields.
- **Access-manager invariant:** runs after status, rank, archive and membership writes (D-059, OI-021 a).
- **Model:** membership changes (D-097), archiving (D-088, D-095, D-098), personal-id normalization (D-066).
- **Isolation:** identity data is dropped on an identity change; sample data only in test files.
- **Workflow:** in M1 commits, only `i18n` with `ui` share a commit; the decision index follows its changes.
- **Design:** `Design.md` matches the tokens and surfaces built, except note 7.
- **Not checked:** Playwright and the build were not run (the build writes files). Code was read by risk, not line
  by line: `unit-tree.spec.ts`, some primitives and most of the dictionary were not read.
