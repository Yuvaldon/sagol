## Findings

### 1. Link review target

`ReviewAccountLinkInput` resolution `link` takes any `soldier_id`
(`src/contracts/inputs/accounts.ts:41`). `canReviewLinkRequest` checks authority over any one
candidate (`src/domain/accounts/matching.ts:120`). OI-023 (d) did not require the chosen soldier to
be a candidate or to be covered by `accounts:approve`. It also omitted `soldiers:create` for
`create_soldier`, and the rule that auto-link needs a verified email. An approver of platoon 1 could
link an identity to a soldier of platoon 2, which is the takeover the Why of D-005 prevents.
Decisions: D-005, D-030, D-066, iron rule 6. Owner: data.

### 2. Escalation guard coverage

OI-021 (b) names `grantAccess` and role permission-set writes. Contracts also let a role be given
through `CreateRankRoleBindingInput.role_id` and updates of a binding,
`UpdateOrganizationInput.baseline_role_id`, and `UpdateSoldierInput.command_rank_id`. Someone holding
`roles:create` could bind the owner role to their own rank. Decisions: D-060, D-003. Owner: data.

### 3. Invalid time zone

`organizations.timezone` accepts any string of 1 to 64 characters
(`src/contracts/entities/organization.ts:11`). `todayIn` then throws `RangeError`
(`src/domain/time/index.ts:19`), confirmed with `Asia/Jerusalm`. One typo at bootstrap or in
`updateOrganization` stops every command that needs "today". Decisions: D-046, D-053. Owner:
contracts or domain (OI-035 asks which), and the data layer calls the check.

### 4. Holder without seniority

`rankAllows` answers for the holder's own record (`src/domain/policy/can.ts:23`) before the
holder-without-seniority check (`:25`). D-057 says such a holder gets only `any` permissions. No
matrix row covers the case, and phase 8 will copy the behavior to SQL. Decision: D-057. Owner: domain.

### 5. Reason on update

OI-023 (a) called `leaveReasonIssues` on creation and type change only, so an `update` that blanks
`reason` on a `requires_reason` type would pass. Decision: D-064. Owner: data.

### 6. Duplicate `LinkCandidate`

`src/domain/accounts/matching.ts:26-28` defines `LinkCandidate` and `LinkMatchKind`. The contract
defines `LinkCandidate` and `LinkCandidateMatch` at `src/contracts/repositories/index.ts:132-136`.
Iron rule 3: vocabularies belong to contracts. Owner: domain.

### 7. Invite links

OI-026 targeted a row that did not exist. Session 0.7 gave it V9, so the planning part is settled.
Still true: searching only the unit's soldiers changes `linkCandidates` and `linkReviewTargets`
(D-066), which is domain work on top of the schema and contracts change.

### 8. Clock

OI-004 had no target. Session 0.7 gave it V0, so the planning part is settled. Still open: domain
reads no clock (D-053), the data layer needs the current time for audit columns from its first
command, `DataAdapterFactory` takes only `identity` (`src/contracts/commands/index.ts:256`), and no
decision says who reads the time.

### 9. Property references

D-065 leaves the `soldier_ref` and `unit_ref` row check to the data layer. OI-023 (b) names only
`propertyValueIssues`, and no domain function lists the ids that properties reference, unlike
`filterReferences` for filters. Definitions arrive in V14, so no such value can exist before it.
Owner: domain and data.

### 10. Blocking decisions

OI-007, OI-017, OI-018 and OI-026 blocked the old data phase. Session 0.7 settled it: OI-007 by
D-080, OI-017 by D-079, OI-018 asked at V12, OI-026 asked at V9.

### 11. ARCHITECTURE

The layer table said config imports contracts only, while `src/config/{env,palette,views}` import
`zod`, as D-074 implies and `.dependency-cruiser.cjs` allows. The domain folder line omitted
`accounts/`, `tags/`, `issues/`, `json/` and `time/`. Fixed in 0.8 by editing ARCHITECTURE. No new
decision entry was added.

### 12. Decision index

The D-030 row omitted D-069, against D-062. Fixed in 0.8. It was the only gap between the index and
the status lines of the entries.

### 13. Access-manager invariant

`isAccessManager` (`src/domain/policy/invariants.ts:14`) ignores `subject_rank_constraint`, so a
holder limited to `junior`, or one without seniority, counts as a full manager. No test covers it.
Decision: D-059. Owner: domain.
